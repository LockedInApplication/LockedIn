# Date spots in chat

Apply the additive `20261119003000_date_spots` migration before serving the new API. The database stores one private saved area and ordered interests per account, one active request per conversation, and an optional public place ID on a chat message. No existing conversation needs a backfill.

- Leave `DATE_SPOTS_ENABLED=false` while deploying the compatible web and API builds. Set it to `true` after checking that the migration is applied and Geoapify usage is appropriate for the existing API plan. The feature uses `DISCOVERY_GEOAPIFY_API_KEY` unless a dedicated `DATE_SPOTS_GEOAPIFY_API_KEY` is set on the API.
- Confirmed Discovery metros also work as public meetup areas; the four listed pilot cities have fallback centers and a shortlist of public subareas if they appear in `DISCOVERY_AREAS_JSON`. Subarea reference points are from GeoNames: [New York](https://www.geonames.org/search.html?q=new+york+city), [West Hartford](https://www.geonames.org/4845415/town-of-west-hartford.html), [East Hartford](https://www.geonames.org/advanced-search.html?q=Town&startRow=2150), [Accra](https://www.geonames.org/advanced-search.html?country=GH&q=&startRow=250), and [Asokwa](https://www.geonames.org/advanced-search.html?country=GH&q=&startRow=350). To add neighborhoods or transit hubs, configure `DATE_SPOT_AREAS_JSON` on the API. Use only broad public areas, not anyone’s address or device coordinates. Changes here do not change Discovery markets.
- To verify the rollout, test a solo search, one-tap acceptance with saved preferences, a declined request, a shared place opened from the other account, and photo-unavailable fallback in both an accepted Discovery chat and a direct-invite conversation. With the gate disabled, plain chat still works and shared venue messages retain their text.

Solo searches use only the requester’s inputs; a current Discovery city can prefill their starting area, and published profile interests can prefill recognized categories. Mutual searches consume the inputs captured separately when each person starts or accepts the same request. Leaving a search or explicitly withdrawing it never modifies Discovery visibility. Requests are valid for 24 hours; a read of an expired request removes it, and either person can end a request earlier. Blocking or closing a chat clears its request. Saved preferences are private and removable.

Geoapify receives only a public search center/radius and general venue categories, not account identifiers. Venue details come from Geoapify and its OpenStreetMap source. Photos require a linked Wikimedia Commons image and usable license metadata; missing photos, unsupported hours and addresses are not fabricated. The browser loads attributed photo thumbnails only when the venue is opened. People only see public venue details and a short explanation; starting areas and individual travel distances are never returned to their match. Approximate straight-line distance is not a travel-time estimate.
